# H9 프로젝트 수익률 관리

프로젝트마다 **① 계약 시점 수익률(기준)** 과 **② 확정 시점 수익률(실적)** 을 각각 입력하고,
**변동과 원인**을 관리하는 웹 프로그램입니다. 프로젝트와 직원 명부는 **구글시트에서 일괄 등록**합니다.

> v2.0 재구축 — 테이블 접두사 `h9_`. 구버전(`mt_`) 데이터와 완전히 분리되어 있으며,
> 구버전 테이블은 `POST /api/drop-legacy` 로 정리할 수 있습니다.

## 화면 (4개 탭)

- **대시보드** — 전체 요약(등록·**진행중**·**완료** 건수, **계약액 합계**·**확정 매출 합계**(각각 `전체 N건`·`완료 M건` 기준 표시), 계약 수익률, 확정 수익률·변동),
  **프로젝트별 수익률 변동 막대그래프**(계약/확정 두 막대를 나란히, 프로젝트가 많으면 **좌우 스와이프**
  — 터치 스와이프·마우스 드래그·[←][→] 버튼, 막대를 누르면 그 프로젝트 입력 화면으로 이동),
  프로젝트별 두 시점 수익률 비교표, 유형별(정산 형태) 수익률, CSV 내보내기
- **프로젝트 수익률** — 한 화면에서 계약 시점과 확정 시점을 같은 구조로 입력.
  변동 분석표(매출·인건비·외주비·부대비 항목별 차이와 수익률 영향) +
  **인건비 변동 상세** — 어느 소속에서 MM이 늘거나 줄었는지, 등급이 상향·하향됐는지,
  신규 투입·투입 제외인지를 문장으로 서술하고 소속×등급별 표로 보여줍니다.
  변동 사유·이력, 데이터 초기화
- **직원 명부 · 단가** — 소속·이름·등급 관리, 소속별·등급별 단가표.
  명부는 **10명까지만 보이고 그 안에서 스크롤**되며(머리글 고정), 10명 이하면 그대로 다 보입니다.
  명부와 단가표 모두 **엑셀 업로드 · 구글시트 · 붙여넣기**로 일괄 등록합니다.
  **[직원 소속 채우기]** 를 누르면 명부에 있는데 단가표에 없는 소속을 자동으로 넣습니다
  (`CTO직속`·`CEO직속` 은 **PM 단가를 그대로 복사**, 나머지는 닮은 소속의 단가를 가져오고
  찾지 못하면 0 으로 넣어 직접 입력하게 합니다)

- **매뉴얼** — 관리·입력 절차와 유의사항을 한 장으로 정리한 읽기 전용 화면.
  전체 흐름(7단계) · 단계별 상세(어디서/무엇을/유의사항) · 계산 규칙 · 반드시 알아야 할 유의사항 8가지 ·
  일괄 등록 시트 형식 · 소속 이름 자동 해석 · 자주 겪는 문제 · 용어.
  상단에 **개발 스펙 요약 박스**(개발 언어·런타임, 백엔드·프론트엔드, DB·테이블, GitHub, 호스팅,
  로그인·보안, 외부 연동, 동시 사용, 구축 이력, 코드 규모, 환경변수)가 있고,
  아래에 **업데이트 히스토리**(버전별 변경 내용, 현재 버전 강조)가 함께 있습니다.
  새 버전을 낼 때는 `APP_VERSION` 을 올리고 `CHANGELOG` 맨 위에 한 줄 추가합니다.

모든 삭제는 **[정말 삭제하시겠습니까?] 확인창**을 거칩니다. 무엇이 지워지는지(프로젝트명과 투입 행 수,
직원 소속·등급, 단가표 소속과 그 단가를 쓰는 직원 수)를 보여주고, `Esc`·바깥 클릭·[취소]로 중단됩니다.
명부 전체 대체는 빠지게 될 직원 이름을 먼저 보여줍니다.

## 계산 규칙

| 항목 | 산식 |
|------|------|
| 계약 시점 수익률 | (계약액 − (Σ 계약MM × **저장된 단가** + 계약 외주비 + 계약 부대비)) ÷ 계약액 × 100 |
| 확정 시점 수익률 | (실제 매출 − (Σ 실투입MM × 단가 + 실제 외주비 + 실제 부대비)) ÷ 실제 매출 × 100 |
| 수익률 변동 | 확정 시점 − 계약 시점 (%p) |

> **용어** — 금액·수익률 이름은 **확정 매출 · 확정 수익률 · 확정 시점**이고,
> 프로젝트 **상태**값은 그대로 `진행중` / `완료` / `보류` 입니다. 둘은 다른 개념입니다.

### 계약금액은 시작과 끝이 같습니다

고객사에서 받는 **계약금액은 계약 시점과 확정 시점이 동일**합니다. 등급이 올라가거나 MM이 늘어도
고객사에서 더 받는 것이 아니므로 **매출은 그대로고 원가만 달라집니다** — 즉 수익률 변동은 사실상
**투입 인력의 등급·MM 변동**에서 나옵니다.

- **실제 매출을 0으로 비워 두면** 계약액을 그대로 씁니다. 칸 아래에 적용되는 금액이 표시됩니다.
- 변동 분석표의 매출 행에는 **계약금액 변동 없음**으로 표시됩니다.
- **감액 정산·과업 축소처럼 실제로 받는 금액이 달라진 경우에만** 실제 매출을 다르게 입력합니다.

### 유형(정산 형태) 표기 통합

유형은 자유 입력이라 `월정산` / `월 정산` 처럼 표기가 갈릴 수 있습니다.

- 유형별 수익률은 **공백·대소문자를 무시해 한 묶음으로 집계**하고, 가장 많이 쓰인 표기를 대표로
  보여 줍니다 (갈린 표기는 이름 옆에 함께 표시).
- 유형 입력칸에 **이미 쓰인 유형 목록**이 뜨므로 골라 넣으면 새 변형이 생기지 않습니다.
- 저장된 값까지 맞추려면 유형별 수익률 옆 **[표기 통일]** — 무엇이 어떻게 바뀌는지 먼저 보여주고
  확인을 받은 뒤, 유형 이름만 대표 표기로 바꿉니다 (금액·수익률은 그대로).

### 대시보드 합계의 두 기준

합계 행에서 **계약액은 전체**(진행중·보류 포함), **확정 매출은 완료 + 실적 입력된 건만** 더한 값입니다.
각 열 아래에 `전체 N건` / `완료 M건` / `짝 K건` 으로 기준이 표시되고, 표 아래에 두 금액의 차액이
어디서 나오는지(진행중·보류·실적 미입력 건수)를 문장으로 설명합니다. 같은 기준으로 보려면
상태 필터를 `완료` 로 바꿉니다.

### 진행중 프로젝트는 변동 집계에서 제외

진행중인 프로젝트는 아직 최종 실적이 아니므로 **대시보드의 확정 수익률·변동 집계에 넣지 않습니다.**

- 요약 카드의 **확정 수익률**과 변동은 상태가 `완료` 이고 실적이 입력된 프로젝트만 모아 계산하며,
  변동은 **그 완료 프로젝트들의 계약 기준 수익률과 비교**합니다 (전체 평균과 섞지 않습니다).
- 진행중 프로젝트의 변동은 표에서 <code>잠정</code> 으로 흐리게 표시되고 합계 행에서 빠집니다.
  CSV 에도 `변동확정` 열로 `확정` / `잠정(진행중)` 이 함께 나갑니다.
- **진행중 / 완료 건수 카드**가 따로 있어 진행중 계약액·계약 기준 수익률과
  완료 건수·실적 입력 건수를 한눈에 봅니다. 유형별 표에도 `진행중 / 완료` 열이 있습니다.
- 최종 변동으로 반영하려면 프로젝트 **상태를 `완료`로** 바꾸면 됩니다.

- 두 시점의 투입 표는 **구조가 같습니다** — 소속 · 등급 · 단가/MM · MM. 소속·등급을 고르면 단가표에서
  단가가 채워지고, 실제 단가가 다르면 직접 수정할 수 있습니다. **[← 계약 투입 복사]** 는
  **계약액·외주비·부대비와 투입 인력을 그대로** 가져오므로 달라진 부분만 고치면 됩니다.
- 숫자 칸이 **0일 때 클릭하면 0이 지워집니다** (0이 남아 앞에 입력하면 자릿수가 하나 늘어나던 문제 방지).
  비운 채로 벗어나면 0으로 돌아갑니다.
- 계약 시점 단가는 저장 시점 값으로 고정되어 기준이 흔들리지 않습니다.
- 실제 매출을 0으로 두면 계약액과 동일하게 봅니다.

## 일괄 등록 (엑셀 업로드 · 구글시트 · 붙여넣기)

프로젝트와 직원 명부 모두 세 가지 방법을 지원합니다.

**중복은 등록되지 않습니다.** 같은 시트를 몇 번 올려도 새로 생기지 않고 기존 건이 갱신됩니다.

- **프로젝트** — ① 프로젝트번호 ② 이름(앞뒤·중간 공백과 대소문자 무시)으로 기존 건을 찾습니다.
  번호로 못 찾아도 같은 이름이 이미 있으면 그 건을 갱신하고 번호를 채워 넣습니다.
  한 번에 같은 프로젝트가 여러 탭에 나뉘어 있으면 **하나로 합쳐서** 등록하고
  (빈 항목만 채우고 투입 행은 이어 붙임), 결과 메시지에 합친 건수를 알려줍니다.
- **직원 명부** — 이름으로 기존 직원을 찾아 갱신합니다. **동명이인은 그대로 유지**되고
  (같은 이름이 시트에 2번 나오면 기존 2명에 차례로 매칭), 시트 안에서 내용까지 똑같이
  반복된 줄은 한 번만 반영하고 제외 건수를 알려줍니다.

1. **엑셀 파일 업로드** — `.xlsx` · `.xls` · `.csv` 를 그대로 올립니다. 구글시트 권한 설정이
   필요 없어 가장 확실한 방법입니다. CSV 는 UTF-8 · CP949(한글 윈도우) · BOM 모두 자동 인식합니다.
2. **구글시트 링크** — 현재 탭 / 모든 탭 일괄. `export` → `gviz` → `pub` 순으로 시도하고,
   **웹에 게시** 링크와 Apps Script 웹앱(CSV/JSON) 응답도 지원합니다.
3. **붙여넣기** — 시트 범위를 복사해 넣습니다.

**단가표**도 같은 방식으로 일괄 등록합니다. 두 가지 형태를 인식합니다 —
**가로형**(첫 열 소속 + `초급`·`중급`·`고급`·`특급` 열, 순서 무관) 과
**세로형**(`소속`·`등급`·`단가` 3개 열). 금액의 쉼표·"원"·공백은 자동 제거되고,
제목 행이 위에 있어도 머리글을 찾아냅니다. 기본은 **겹치는 소속만 갱신**이고,
체크하면 전체 대체합니다.

한 번 등록하면 프로젝트 투입 행에서 **소속·등급을 고르는 순간 단가가 자동으로 채워집니다.**
시트 공유는 **[공유] → 일반 액세스 → "링크가 있는 모든 사용자"**, 역할은 **뷰어(보기)** 로 두면 됩니다.
편집 권한은 필요 없고 **보기 권한만으로 읽어옵니다.** 권한이 없으면 화면에 설정 방법이 안내됩니다.

**프로젝트** — 머리글에서 자동 인식: `프로젝트명`(또는 계약명, 필수) · `프로젝트번호` ·
`클라이언트`(고객사) · `상태` · `시작` · `종료` · `MM` · `금액` · `정산 형태` · `파트` · `등급` ·
월별 열(`25'10월` `1월` `2026-01` 형태). `프로젝트번호` 처럼 번호·코드가 붙은 열은
프로젝트명으로 쓰지 않고 번호로 분리하며, **번호가 있으면 번호로 기존 프로젝트를 찾아 갱신**하므로
이름이 바뀌어도 중복 생성되지 않습니다.
계약명이 병합 셀이라 아랫줄이 비어 있어도 파트 행들을 하나의 계약으로 묶습니다.
파트·등급·MM이 있으면 **계약 시점 투입계획**으로 함께 등록되며, 월별 열이 있으면 그 합을 파트 MM으로 씁니다.
`MM 당 단가` 처럼 단가가 들어간 열은 MM 열로 쓰지 않습니다.

**직원 명부** — 인력 현황 시트의 `번호` · `부서(실)` · `부서(팀)` · `이름` · `기술등급(SDS)` ·
`등급분류기준(경력)` 을 자동 인식합니다 (번호는 무시, 열 순서 무관, 제목 행이 위에 있어도 됩니다).
**부서(팀)이 `-` 인 직원은 그 실의 실장**으로 등록되고, `등급분류기준`·`경력` 열은 기술등급과 구분해
따로 저장합니다. [모든 탭 일괄]은 이름에 **현황**이 들어간 탭이 있으면 그 탭만 가져옵니다.
기본은 **명부 전체 대체**(목록에 없는 직원은 삭제, 투입 이력이 있으면 재직 해제)입니다.

파트·소속 표기는 단가표 소속으로 자동 해석됩니다: `GUI`·`PUB`·`UI` → Visual,
`DEV`·`BE`·`FE`·`QA` → 서비스개발, `기획` → UX.
**`CTO`·`CEO`(대표) 직속 조직은 모두 PM 단가 기준을 따릅니다** — `CTO직속` `CTO 직속실`
`CEO직속` `대표이사 직속` 처럼 표기가 달라도 PM 단가로 계산됩니다.
나머지는 이름 유사도로 매칭하고, 못 찾으면 미리보기에 경고로 표시됩니다.
(단가표에 같은 이름의 행이 있으면 그 행이 항상 우선입니다.)

## 여러 PM이 동시에 사용하기

여러 명이 같은 주소로 동시에 접속해 각자 맡은 프로젝트를 입력할 수 있습니다.

- **담당 PM** — 프로젝트마다 담당자를 지정하고, 대시보드에서 **[내 프로젝트만]** 으로 걸러 봅니다.
  프로젝트별 수익률 목록은 **담당 PM 기준으로 묶여 정렬**되고(그 안에서는 프로젝트명 순),
  **담당 PM 셀렉트**로 한 사람만 골라 볼 수 있습니다 (이름 옆에 담당 건수, `담당 미지정` 도 선택 가능).
  선택하면 위 변동 막대그래프와 합계 행도 그 사람 것만 계산합니다. 상태 필터와 함께 걸립니다.
  시트에 `담당 PM` 열이 있으면 일괄 등록 시 함께 들어옵니다.
  담당 PM 목록에는 **소속·팀·직책에 PM 이 들어간 직원**과, PM실이 아니어도 프로젝트를 맡는
  **인터렉션실 이은택 실장 · DT개발실 최용석 실장**이 뜹니다(코드의 `EXTRA_PMS` 에 이름을 추가하면 늘릴 수 있습니다).
  이미 지정된 담당자는 목록에서 사라지지 않으며,
  클라이언트 목록에는 **등록된 프로젝트의 고객사만** 가나다순으로 뜹니다.
- **입력자** — 헤더의 **입력자** 칸에 이름을 넣으면(브라우저에 저장) 최종 수정자와
  변동 이력 작성자로 기록됩니다. 로그인은 공용 비밀번호 하나이므로 이 이름이 누가 입력했는지를 남깁니다.
- **동시 편집 보호** — 같은 프로젝트를 두 사람이 열어 두고 저장하면, 나중에 저장하는 쪽이
  **차단되고 누가 먼저 저장했는지 안내**됩니다(먼저 저장한 값이 보존). 서로 다른 프로젝트는 동시에 저장해도 문제 없습니다.
  판정은 `UPDATE ... WHERE updated_at <= baseUpdatedAt` 한 문장으로 처리해, 조회와 갱신 사이에 다른 저장이
  끼어드는 경우까지 막습니다.
- **프로젝트번호 중복 차단** — 번호에 unique 제약이 있어 동시에 일괄 등록해도 같은 번호가 두 건 생기지 않습니다.
- **저장 안 한 입력 보호** — 입력 중 변경이 있으면 저장바에 **● 저장 안 된 변경 있음**이 뜨고,
  그 상태에서는 자동 새로고침이 **화면 값을 덮어쓰지 않습니다.** 그 사이 다른 사람이 저장했으면
  덮어쓰는 대신 경고만 띄웁니다. [새로고침]·프로젝트 이동·창 닫기도 먼저 확인을 받습니다.
- **최신 데이터 반영** — 헤더 **[새로고침]** 버튼, 그리고 다른 창을 보고 돌아오면 자동으로 다시 읽습니다
  (저장 안 한 입력이 없을 때만).

## 기술 스택

- 백엔드: Node.js + Express + `pg` (Supabase Session pooler)
- 프론트: 정적 HTML/JS 단일 파일 (`public/index.html`)
- DB: Supabase PostgreSQL — `h9_settings` `h9_rates` `h9_staff` `h9_projects` `h9_rows` `h9_logs`
- 서버 시작 시 스키마를 자동 생성하고 기본 단가표를 시딩합니다 (별도 setup 불필요)

## 탭과 주소 (브라우저 뒤로가기)

탭을 옮기면 주소에 `#dash` `#proj` `#staff` `#man` 이 기록됩니다.

- 브라우저 **[뒤로]** 를 누르면 **이전 탭**으로 돌아갑니다 (로그인 화면이 아닙니다).
- 앱을 열면 주소가 `#dash` 로 맞춰지므로, 다른 탭에서 [뒤로] 한 번이면 **대시보드**로 돌아옵니다.
- 새로고침해도 보던 탭이 유지되고, `.../#staff` 처럼 특정 탭 주소를 공유할 수 있습니다.
- 로그인 후 이동은 `location.replace` 로 처리해 **로그인 화면을 기록에 남기지 않습니다.**
  이미 로그인된 상태로 로그인 화면에 들어가면 자동으로 앱으로 되돌아갑니다.
- 저장하지 않은 입력이 있으면 탭을 오가도 **화면 값을 다시 불러오지 않아** 입력이 보존됩니다.

## 로그인 (통합 계정)

PMO 프로젝트 관리(h9-pmo)와 **계정·권한을 하나로 공유**합니다.

- 로그인 = **회사 메일 계정**(`@hnine.com`) + 비밀번호
- 상단 공통 바에서 두 사이트를 오갈 수 있습니다
- 관리자는 상단바 **계정 관리**에서 등록 / 제한 / 권한 변경 / 비밀번호 초기화 가능
  (어느 앱에서 바꾸든 양쪽에 즉시 반영됩니다)
- `OIDC_PROVIDER=google` 과 클라이언트 ID/시크릿을 넣으면 **로그인 화면 없이**
  바로 구글로 넘어갑니다. 브라우저에 회사 계정이 로그인돼 있으면 그대로 입장하고,
  아니면 구글 로그인 화면이 뜹니다. (`AUTO_SSO=0` 으로 끄거나, `?pw=1` 로 접속하면
  비밀번호 로그인 화면)
- 기존에 쓰던 단일 비밀번호는 `ADMIN_EMAIL` 계정으로 **그대로 승계**됩니다
- **`SESSION_SECRET` 은 h9-pmo 와 반드시 같은 값**이어야 합니다

> 입력자 이름은 로그인 계정 이름으로 자동 설정됩니다(직접 수정 가능).
